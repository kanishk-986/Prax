Anything that writes was done on the demo profile `/w/demo-layla-haddad`; the real profile `/w/shashi-pal-p16q` was only looked at. Every bug found live was checked against `main` and fixed on branch `qa-fixes`. The Prax extension is **not installed in this Chrome profile** (the Extension page shows Step 1, and the bridge does not answer), so no AI call ran; the AI buttons were tested for what they do without it.

Result key: **Works**, **Fixed** (cause and fix below), **Can't fix** (with the reason), **Needs user action**.

## The five causes behind the dead buttons

1. **Every AI button waited up to two minutes when the extension is missing.** `askExtension` (`src/lib/bridge.ts`) posted to the bridge and only gave up at its timeout (120 s by default, 90 s in Content Studio). With no extension, Classify sat on "Reading", Ask on "Thinking", Rewrite on "Rewriting", and so on. **Fix:** `askExtension` first checks the bridge answers (1.5 s, remembered once it has) and otherwise says at once: "Prax for Chrome is not answering in this browser. Install 0.9.3, connect it on the Extension page, then reload this page."
2. **Lists did not show the user's own Add, Save or Delete until a reload.** `useLive` (`src/lib/live.ts`) relied only on Realtime. Supabase never delivers DELETE events on a filtered channel, and on the live site inserts and updates did not arrive either (seen on `templates`, `saved_drafts` and `prospects`). The toast said "Added", "Deleted" or "Removed" and the screen did not change. **Fix:** the browser Supabase client (`src/lib/supabase/client.ts`) fires a `prax:wrote` event after each successful PostgREST write, and every `useLive` list of that table reloads (`writtenTable` in `src/lib/writes.ts`, tested). Realtime still brings other people's changes. *Why Realtime did not deliver inserts could not be checked without SQL or the Supabase dashboard: check that `templates`, `saved_drafts` and `prospects` are in the `supabase_realtime` publication.*
3. **Today, Delete task never sent anything.** The button was `onClick={() => supabase().from("daily_items").delete().eq(...)}`. A Supabase query is lazy: it only goes out when awaited or `.then`'d, so nothing was deleted (the task was still there after a reload). **Fix:** a `remove` handler that drops the row, awaits the delete, and shows "Task deleted" with Undo.
4. **Activity lines were never written.** `logActivity` (`src/components/content/shared.tsx`) returned the lazy query, and most callers did not await it. So Content Studio's "Log as shared" and "Log as reshared", approvals sent or answered, repurposes, and campaign started, paused, resumed, deleted and restored all toasted without saving anything. **Fix:** `logActivity` is async and awaits the insert, so every caller sends it.
5. **Classify (Comment Studio, Voice and rules, Playbooks, "Try it on a real post").** See below.

## The "classify" control

Comment Studio, Playbooks tab, "Try it on a real post": a box and a red **Classify** button.

- A short link (`https://lnkd.in/...`) left Classify greyed out with no reason (it needs 40 characters).
- A full post link enabled it, and then it sat on "Reading" for two minutes, because the extension is not in this browser (cause 1).
- Even with the extension, a link alone was sent to the AI as if it were the post. Prax never opens LinkedIn, so the model would be classifying a URL.

**Fix:** `classifyInput` (`src/lib/studio.ts`, tested) takes the link out and says why Classify cannot run yet: "That is a link only. Prax does not open LinkedIn, so paste the post text as well.", or asks for at least 40 characters. Only the post text is sent. A missing extension now shows an error within about 1.5 s.
